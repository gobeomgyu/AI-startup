# PRD: 소규모 팀 Todo 앱

## 1. 문서 목적

이 문서는 소규모 팀이 함께 사용하는 Todo 앱의 제품 요구사항을 정의한다. 현재 합의된 범위와 아직 결정되지 않은 항목을 구분해 구현 전에 검토할 수 있도록 한다.

## 2. 제품 개요

팀원들이 하나의 로컬 앱과 데이터베이스를 공유하며 작업을 관리한다. 사용자는 작업을 만들고 조회·수정·삭제할 수 있고, 담당 팀원, 마감일, 우선순위, 상태, 태그를 관리할 수 있다.

## 3. 목표와 범위

### 목표

- 소규모 팀의 작업을 한곳에서 관리한다.
- 작업과 팀원 명단을 기본 CRUD 기능으로 관리한다.
- 별도 인증 없이 로컬 환경에서 간단히 실행한다.
- FastAPI가 제공하는 Swagger UI로 API를 확인하고 호출할 수 있게 한다.

### 이번 범위에 포함

- 작업 생성, 목록·상세 조회, 수정, 삭제
- 작업의 제목과 설명, 담당자, 마감일, 우선순위, 상태, 태그 관리
- 팀원 목록의 생성, 조회, 수정, 삭제
- 상태 세 가지 고정: `할 일`, `진행 중`, `완료`
- SQLite 저장, 로컬 배포, FastAPI 내장 API 문서

### 이번 범위에서 제외

- 로그인, 인증, 사용자별 권한
- 실시간 동기화 및 푸시 알림
- 클라우드 배포 및 여러 데이터베이스 서버 간 동기화

## 4. 사용자와 사용 시나리오

### 사용자

앱에 접근할 수 있는 사람은 누구나 동일한 작업과 팀원 명단을 조회하고 변경할 수 있다. 인증과 권한 구분은 없다.

### 주요 시나리오

1. 팀원이 팀원 명단에 자신 또는 동료를 등록한다.
2. 팀원이 작업을 생성하고 담당자, 마감일, 우선순위, 상태, 태그를 지정한다.
3. 팀원이 작업 목록을 확인하고 작업 정보를 수정하거나 삭제한다.
4. 팀원이 작업을 완료하면 상태를 `완료`로 변경한다.
5. 작업에서 담당자를 팀원 목록 중 하나로 선택하거나 담당자를 해제한다.

## 5. 기능 요구사항

### 작업

- 작업은 제목을 필수로 가진다.
- 설명은 선택 항목이다.
- 담당자는 등록된 팀원 중 한 명을 지정할 수 있으며, 미지정도 허용한다.
- 마감일은 선택 항목이다.
- 우선순위는 `낮음`, `보통`, `높음` 중 하나이며 기본값은 `보통`이다.
- 상태는 `할 일`, `진행 중`, `완료` 중 하나이며 기본값은 `할 일`이다.
- 마감일은 `YYYY-MM-DD` 날짜로 저장한다.
- 태그는 작업 생성·수정에서 문자열 배열로 입력한다. 앞뒤 공백을 제거하고 대소문자 구분 없이 기존 태그와 연결한다.
- 작업 PATCH에서 `tags`를 생략하면 기존 연결을 유지하고, 배열을 보내면 전체 교체한다. 더 이상 작업에 연결되지 않은 태그는 보존한다. 별도 태그 CRUD는 제공하지 않는다.
- 작업은 생성·조회·수정·삭제할 수 있다.

### 팀원

- 팀원은 이름을 필수로 가진다.
- 팀원은 생성·조회·수정·삭제할 수 있다.
- 팀원 삭제 시 작업은 유지하고 담당자를 비운다.

### 조회

- 작업 목록과 작업 상세를 조회할 수 있다.
- 작업 목록은 별도 필터·정렬·페이지네이션 없이 전체 작업을 반환한다.
- 팀원 이름 중복을 허용한다.
- 작업 삭제는 영구 삭제한다.

## 6. 비기능 요구사항

- Python 3.11 및 FastAPI를 사용한다.
- 데이터베이스는 SQLite를 사용한다.
- 로컬 환경에서 실행한다.
- API 명세는 FastAPI 내장 Swagger UI(`/docs`)와 OpenAPI 문서로 제공한다.
- 실시간 기능은 제공하지 않는다.

## 7. 성공 기준

- Swagger UI에서 작업과 팀원 CRUD API를 사용할 수 있다.
- 작업에 선택된 팀원, 마감일, 우선순위, 고정 상태, 태그가 저장되고 조회된다.
- 앱을 재시작해도 SQLite에 저장한 데이터가 유지된다.

## 8. 구현 전 확인할 결정 사항

이번 구현에 필요한 제품 동작은 위 기능 요구사항에 확정했다.

# AI 코딩 작업 루프

이 문서는 Codex 등 코딩 에이전트와 사람이 이 저장소에서 기능을 안전하게 완성하는 기본 절차다. 작게 구현하고 빠른 검증 결과를 다음 수정에 바로 반영한다.

## 작업 한 건의 반복 절차

1. **현재 상태 확인:** `git status`, 관련 코드, `AGENTS.md`, 관련 PRD/TSD/DATABASE 및 테스트 케이스를 읽는다. 저장소에 이미 있는 동작을 먼저 찾는다.
2. **작업 범위 확정:** 한 번에 하나의 API 동작이나 명확한 수정만 다룬다. 요구사항이 미정이면 임의 구현하지 말고 명시된 제안만 사용하거나 질문한다.
3. **완료 조건을 테스트로 구체화:** 해당 `TEST_CASE.md` 케이스를 찾아, 아직 테스트가 없다면 먼저 실패를 재현하는 테스트를 작성한다. 성공·실패 응답과 데이터 상태를 확인한다.
4. **최소 구현:** 테스트를 통과시키는 데 필요한 최소 변경을 한다. 주변 파일을 이유 없이 재구성하거나 요구사항 밖 기능을 추가하지 않는다.
5. **짧은 피드백 루프:** 먼저 해당 테스트를 실행하고, 실패하면 진단을 읽어 원인을 수정한다. 테스트를 삭제·약화하거나 검사 규칙을 낮춰 녹색으로 만들지 않는다.
6. **전체 품질 게이트:** `uv run python scripts/check.py`를 실행한다. 이 명령은 Ruff 린트, Ruff 포맷 검사, 앱이 있을 때 Mypy strict 검사, 전체 Pytest를 실행한다. 실패가 남아 있으면 완료로 보고하지 않는다.
7. **변경 검토:** `git diff --check`와 `git diff`를 확인한다. 문서의 확정 요구사항과 구현이 맞는지, 임시 파일·비밀 값·불필요한 변경이 없는지 살핀다.
8. **결과 보고:** 변경 요점, 실행한 검사와 결과, 남은 제한 사항을 보고한다. 커밋은 사용자가 요청했거나 작업 지시가 명확히 커밋을 포함할 때만 만든다.

## 반복 실패 처리

- 같은 검사가 두 번 연속 실패하면 코드를 더 추측해서 고치지 말고, 실패 출력과 관련 요구사항·구성을 다시 확인한다.
- 세 번의 수정 시도 뒤에도 해결되지 않으면 우회·ignore·테스트 약화 대신 현재 원인, 시도, 필요한 결정을 보고한다.
- 요구사항 충돌이나 구현 중 새로 확인한 제품 결정을 발견하면 관련 `docs/` 문서에 기록하고 구현·테스트를 같은 결정에 맞춘다.
- 같은 작업 실수가 반복되면 `AGENTS.md`나 이 문서를 짧은 재발 방지 규칙으로 갱신한다. 세션별 메모를 장기 지침에 복사하지 않는다.

## 검사 위치

- 빠른 개발 루프와 마지막 확인은 `uv run python scripts/check.py`로 실행한다.
- 커밋 직전 hook도 같은 스크립트를 실행한다. 따라서 수동 검사와 커밋 검사의 기준이 갈라지지 않는다.
- 현재 `app/`에 Python 코드가 없으면 Mypy 단계는 안내와 함께 건너뛴다. 테스트가 하나도 없으면 Pytest가 실패해 커밋도 막힌다.
- API 동작 변경은 자동 테스트에 더해 Swagger UI 또는 HTTP 요청으로 실제 응답을 확인한다. 그 수동 확인은 자동 테스트를 대체하지 않는다.

- 감사일: 2026-10-13
- 대상: Todo FastAPI 애플리케이션, SQLAlchemy/SQLite 접근, 설정 및 잠금 의존성
- 기준: `docs/PRD.md`, `docs/TSD.md`, `AGENTS.md`

## 요약

현재 구현은 PRD의 로컬 단일 팀 사용 범위와 일치하며, SQLAlchemy 바인드 파라미터, Pydantic 입력 검증, SQLite 외래 키 검사, 요청별 세션 사용을 확인했다. 잠금 파일의 패키지 49개에 대한 `python -m uv audit --locked` 결과 알려진 취약점이나 악성 패키지 상태는 없었다.

다만 인증·권한은 제품 요구사항에서 명시적으로 제외되어 있다. 따라서 네트워크에 공개하면 API에 접근 가능한 사용자가 작업과 팀원 데이터를 조회·변경·삭제할 수 있다. 서버를 루프백 이외 주소에 바인딩하지 않는 것이 배포 전 핵심 조건이다.

## 범위와 방법

- API 라우트와 Pydantic 스키마, DB 세션/엔진 설정, SQLAlchemy 모델, 프로젝트 의존성 및 비밀정보 관련 패턴을 정적으로 검토했다.
- `uv.lock`을 기준으로 2026-10-13에 `python -m uv audit --locked`를 실행했다. 49개 패키지에 알려진 취약점/불리한 상태가 보고되지 않았다.
- 애플리케이션 테스트 및 동시 요청 테스트 결과도 입력 검증과 장애 동작을 평가하는 보조 증거로 참고했다.
- 침투 테스트, 외부 네트워크 노출 검사, OS/컨테이너 검사, 파일 권한 검증, 장기 취약점 모니터링은 수행하지 않았다. 패키지 감사 결과는 실행일 기준이며 이후 새로 공개되는 취약점을 포함하지 않는다.

## 발견 사항

### 높음 — 인증 없이 모든 CRUD API에 접근 가능

`app/main.py`는 API 라우터를 인증 의존성 없이 등록하고, `app/api.py`는 작업과 팀원에 대한 조회·생성·수정·삭제를 제공한다. 이는 PRD에서 의도한 기능 범위지만, 127.0.0.1 바깥에 서비스하면 네트워크 접근자가 데이터를 읽고 변조하거나 삭제할 수 있다.

**권고:** 현재 로컬 사용에서는 Uvicorn을 `127.0.0.1`에 바인딩한다. LAN/인터넷 배포를 검토할 때는 노출 범위와 인증·권한 요구사항을 먼저 제품 결정으로 확정하고, 그 결정 없이 외부 인터페이스에 바인딩하지 않는다.

### 중간 — 요청 크기와 컬렉션 개수에 상한이 없음

`app/schemas.py`에서 제목·팀원 이름·태그 문자열 길이는 제한하지만 작업 설명은 문자열 최대 길이가 없고, 태그 배열의 원소 수도 제한하지 않는다. 거대한 요청은 파싱·검증·DB 저장 비용과 파일 크기를 키울 수 있다. 본 감사에서는 요청 본문 크기 상한이나 속도 제한을 확인하지 못했다.

**권고:** 서비스 노출 범위가 로컬을 넘어가거나 비신뢰 입력을 받을 경우 설명 길이, 요청 본문 바이트, 태그 개수에 명시적 한도를 두고 서버 계층에도 본문 크기 제한을 둔다.

### 중간 — 목록 응답에 페이지 크기 제한이 없음

`GET /tasks`와 `GET /members`는 전체 행을 반환한다. 데이터가 증가하면 한 요청의 DB 읽기, 직렬화, 메모리 및 응답 전송 비용도 함께 증가한다. 현재 요구사항이 전체 목록 반환으로 정의되어 있으므로 이는 요구사항 위반이 아니라 규모 증가 시 위험이다.

**권고:** 실제 데이터량과 응답시간을 관찰하고, 전체 반환이 운영 한계를 넘기기 전에 페이지네이션/필터링 도입을 제품 요구사항으로 결정한다.

### 낮음 — SQLite 파일은 로컬 디스크 보호에 의존

기본 DB는 `.local/todo.sqlite3`에 저장되며 암호화나 백업 정책은 앱에서 제공하지 않는다. 작업 설명 등 저장 내용은 파일에 접근 가능한 OS 계정과 백업 대상에서 읽을 수 있다.

**권고:** OS 계정 및 백업 접근을 제한하고, 필요한 보존·백업 정책을 정한다. 디스크 손실이나 계정 침해에도 기밀성이 필요해지면 암호화 요구를 별도로 설계한다.

## 확인된 방어 요소

- 입력은 Pydantic 모델과 enum/길이 검증을 통과한다. 태그 이름별 길이, 제목 및 팀원 이름 길이를 제한한다.
- DB 작업은 SQLAlchemy ORM을 통해 수행하며, 감사 범위에서 사용자 입력을 SQL 문자열에 삽입하는 쿼리는 확인하지 못했다.
- SQLite 연결 때 외래 키 검사를 활성화하고 DB 잠금 대기 시간을 설정한다.
- 커밋된 DB 자격 증명/토큰 패턴, 동적 `eval`/`exec` 사용은 검색에서 발견하지 못했다. 이는 해당 패턴 검색에 한정된 결과다.
- API는 PRD상 인증 및 사용자별 권한을 요구하지 않는다. 이 보고서는 그 요구사항을 임의로 추가하지 않았다.

## 우선 조치

1. 로컬 전용 사용 중에는 서버를 루프백 주소에 바인딩한다.
2. 비신뢰 또는 네트워크 입력을 허용하기 전에 설명·태그·본문 크기 제한을 결정한다.
3. 사용자 수와 데이터량이 늘어나면 인증 범위와 목록 페이지네이션을 제품 결정으로 검토한다.
4. `uv audit --locked`를 정기적으로 다시 실행한다.

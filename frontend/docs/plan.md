# TODO 프론트엔드 구현 계획

## 1. 목표와 범위

`C:\Users\LG\test`의 FastAPI 백엔드에 연결되는 Next.js 앱을 만든다. TODO의 모든 제공 기능을 실제 API와 연결하여 완성하고, 한 앱에서 두 디자인 가이드의 테마를 전환할 수 있게 한다.

- 포함: TODO 목록·상세 조회, 생성·수정·삭제, 빠른 상태 변경, 모든 TODO 필드 편집, 별도 설정 화면에서의 테마 선택
- 제외: 인증, 담당자 관리 화면, 별도 관리자 화면
- 담당자: 백엔드에 등록된 담당자 목록을 조회하여 TODO 생성·수정 시 선택
- 앱 진입 주소 `/`는 TODO 목록으로 이동한다. 첫 진입 때 테마 선택을 요구하지 않는다.

## 2. 기술 구성

- Next.js App Router와 TypeScript를 사용한다.
- 백엔드 기준 주소는 서버 환경변수 `TODO_API_BASE_URL`에 둔다. 로컬 기본 설정값은 `http://127.0.0.1:8000`이다.
- 브라우저에서 백엔드로 직접 요청하지 않고 Next.js 서버를 통해 호출한다. 연결 설정과 오류 처리를 한곳에 모은다.
- `.env.example`에 환경변수 예시를 기록하고, 로컬 설정은 `.env.local`에 둔다.
- 인증 정보는 사용하지 않는다.

## 3. 화면과 동작

### TODO 목록 (`/tasks`)

- `GET /api/v1/tasks`로 전체 TODO를 조회한다.
- 제목, 상태, 우선순위, 담당자, 마감일, 태그를 읽기 쉽게 표시한다.
- 상태·우선순위 필터와 정렬을 제공한다. 백엔드 목록 API에는 필터·정렬·페이지네이션이 없으므로 현재 받은 목록에서 처리한다.
- 새 TODO를 생성한다. 제목은 필수이며 설명, 담당자, 마감일, 우선순위, 상태, 태그를 입력할 수 있다.
- 생성 성공 후 목록과 상세에 저장 결과를 반영한다. 취소 시 저장하지 않으며, 요청 중 중복 제출을 막는다.
- 빈 목록, 로딩, 요청 실패 상태를 표시한다.

### TODO 상세 (`/tasks/[id]`)

- `GET /api/v1/tasks/{task_id}`로 정보를 조회한다.
- 제목, 설명, 담당자, 마감일, 우선순위, 상태, 태그와 생성·수정 시각을 표시한다.
- `PATCH /api/v1/tasks/{task_id}`로 제목, 설명, 담당자, 마감일, 우선순위, 상태, 태그를 수정하고 상태를 빠르게 변경한다. 담당자·마감일·설명은 값을 지울 수도 있다.
- 저장 성공 후 최신 값을 표시한다. 취소 시 변경사항을 폐기하며, 저장 중 중복 제출을 막는다.
- 삭제 전 확인을 받은 뒤 `DELETE /api/v1/tasks/{task_id}`를 호출하고 목록으로 이동한다.
- 삭제 취소 시 데이터를 유지하고, 삭제 실패 시 상세 화면에서 재시도할 수 있게 한다.
- 존재하지 않는 ID, 저장 실패, 삭제 실패를 처리한다.

### 설정 및 테마 선택 (`/settings`)

- 앱 내 탐색 메뉴에서 별도의 설정 화면으로 이동한다.
- 설정 화면에서 Warm Focus와 Kinetic Clarity의 미리보기를 보여주고 선택할 수 있게 한다.
- 기본값은 Kinetic Clarity로 한다.
- 선택 즉시 앱 전체에 적용하고 브라우저에 저장하여 새로고침 후에도 유지한다.
- 두 테마는 화면 구조와 기능을 공유하고 색상, 표면, 경계선, 그림자, 상태 표현을 테마 토큰으로 전환한다.

## 4. 디자인 적용

- 기준 문서: `docs/DESIGN-warm.md.txt`, `docs/DESIGN-productivity.md.txt`
- 가이드의 토큰 정의를 우선 사용하고, 설명 문단과 값이 다른 부분은 화면의 대비와 일관성을 확인하며 결정한다.
- 공통 타이포그래피는 Inter, 코드·숫자 표시는 JetBrains Mono를 사용한다.
- 데스크톱의 밀도 높은 작업 화면을 유지하면서 태블릿과 모바일에서는 탐색 및 상세 정보가 한 열로 재배치되도록 한다.
- 키보드 포커스, 명확한 입력 오류, 충분한 대비와 터치 영역을 확인한다.

## 5. API 연결

| 기능                | 백엔드 API                       |
| ------------------- | -------------------------------- |
| TODO 목록           | `GET /api/v1/tasks`              |
| TODO 생성           | `POST /api/v1/tasks`             |
| TODO 상세           | `GET /api/v1/tasks/{task_id}`    |
| TODO 수정·상태 변경 | `PATCH /api/v1/tasks/{task_id}`  |
| TODO 삭제           | `DELETE /api/v1/tasks/{task_id}` |
| 담당자 선택         | `GET /api/v1/members`            |

TODO 입력은 백엔드 스키마에 맞춘다. 제목은 필수, 상태는 `todo`·`in_progress`·`done`, 마감일은 `YYYY-MM-DD`, 태그는 문자열 배열이다. 우선순위는 백엔드가 제공하는 세 값과 정확히 매핑한다. 수정 시 태그 배열을 보내면 기존 연결이 전체 교체되므로 편집 화면에서 전체 태그 목록을 제출한다. 태그를 모두 제거할 때는 빈 배열을 보낸다. 선택 필드를 비울 때는 API가 요구하는 `null`을 명시적으로 보낸다. API의 `404`와 `422` 응답을 사용자에게 이해할 수 있는 상태와 입력 오류로 표시한다.

## 6. 구현 순서

1. Next.js 프로젝트와 환경변수 예시를 구성한다.
2. API 타입·요청 함수 및 오류 처리를 만든다.
3. 공통 레이아웃, 컴포넌트, 두 테마의 토큰과 전환 기능을 만든다.
4. TODO 목록 및 생성 동작을 구현한다.
5. TODO 상세, 수정, 빠른 상태 변경, 삭제 동작을 구현한다.
6. 별도 설정 화면과 테마 전환을 완성하고 화면별 반응형·접근성을 점검한다.
7. 실제 백엔드와 연결하여 조회·생성·전체 필드 수정·상태 변경·삭제 흐름을 검증하고 발견한 문제를 수정한다.

## 7. 완료 기준

- `/`로 진입하면 TODO 목록이 열리고, 테마는 별도의 `/settings` 화면에서 변경한다.
- 목록에서 TODO를 생성하고 상세에서 모든 필드를 수정·상태 변경·삭제할 수 있으며, 새로고침 후에도 결과가 백엔드에 그대로 남는다.
- 기존 담당자를 선택할 수 있고 태그·마감일·우선순위가 정확하게 저장·표시된다.
- 담당자·마감일·설명을 지우거나 태그를 모두 제거하는 수정도 정상적으로 저장된다.
- 두 테마에서 동일한 작업을 수행할 수 있고 선택한 테마가 새로고침 후에도 유지된다.
- 빈 목록, API 연결 실패, 유효하지 않은 입력, 없는 TODO에 대한 안내가 표시되고 사용자가 해당 작업을 재시도할 수 있다.
- 데스크톱과 모바일에서 주요 작업을 완료할 수 있다.

# TODO 프론트엔드 테스트 케이스

## 1. 목적과 범위

이 문서는 `docs/plan.md`의 완료 기준을 검증한다. TODO 목록·상세, 생성·수정·삭제, 전체 필드, 오류 처리, 별도 설정 화면의 테마 전환을 대상으로 한다. **사용자가 브라우저에서 직접 수행할 수동 테스트 시나리오**를 아래에 포함한다.

- 대상 프론트엔드: Next.js 앱 (`/`, `/tasks`, `/tasks/[id]`, `/settings`)
- 대상 백엔드: `TODO_API_BASE_URL=http://127.0.0.1:8000`
- 범위 제외: 인증, 담당자 관리 화면, 관리자 화면, Playwright를 이용한 E2E 테스트
- 판정: 각 케이스의 기대 결과를 모두 만족하면 통과. 실패하면 실제 결과, 재현 순서, 화면 캡처 또는 콘솔·서버 오류를 기록한다.

## 2. 테스트 준비

1. 백엔드와 프론트엔드를 실행하고 프론트엔드의 `TODO_API_BASE_URL`이 백엔드 주소를 가리키는지 확인한다.
2. 다른 사람의 데이터를 건드리지 않도록 테스트용 데이터베이스를 사용한다. 아래 케이스에서 만든 TODO만 삭제한다.
3. 담당자 선택을 시험하려면 백엔드에 테스트용 담당자 한 명을 미리 등록한다. 담당자 관리 UI는 이번 범위가 아니므로 백엔드의 `/docs`에서 `POST /api/v1/members`를 사용할 수 있다. 이름 예시: `프론트 테스트 담당자`.
4. 테마 기본값 테스트는 이전 선택 기록이 없는 브라우저 프로필 또는 사이트 저장 데이터를 지운 브라우저에서 시작한다.
5. 테스트 TODO 제목에는 `프론트 수동 테스트`처럼 검색하기 쉬운 문구를 사용하고, 생성된 ID를 기록한다.

테스트 기록 양식: `ID / 실행 날짜 / 브라우저·화면 크기 / 통과·실패 / 실제 결과·증거`.

## 3. 사용자가 직접 수행할 수동 테스트 시나리오

### A. 진입·탐색·목록

| ID   | 절차                                                                          | 기대 결과                                                                      |
| ---- | ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| M-01 | 주소 `/`로 접속한다.                                                          | TODO 목록으로 이동한다. 테마 선택을 먼저 요구하지 않는다.                      |
| M-02 | `/tasks`에서 기존 TODO를 선택한 뒤 목록으로 돌아간다.                         | 선택한 TODO의 상세 정보가 열리고 목록으로 돌아갈 수 있다.                      |
| M-03 | 테스트용 DB에 TODO가 하나도 없는 상태에서 `/tasks`를 연다.                    | 빈 목록 안내와 새 TODO 생성 경로가 표시된다. 오류 화면으로 취급하지 않는다.    |
| M-04 | 상태와 우선순위가 다른 TODO를 여러 개 만든 뒤 목록의 각 필터와 정렬을 바꾼다. | 선택 조건과 순서대로 표시된다. 조건을 해제하면 전체 목록이 다시 보인다.        |
| M-05 | 제목·상태·우선순위·담당자·마감일·태그가 있는 TODO를 목록에서 확인한다.        | 각 필드가 상세 데이터와 일치하고 날짜·상태·우선순위를 알아볼 수 있게 표시한다. |

### B. TODO 생성

| ID   | 절차                                                                                            | 기대 결과                                                                                                    |
| ---- | ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| M-06 | 새 TODO에서 제목 `프론트 수동 테스트 - 기본`만 입력해 저장한다.                                 | 한 건만 생성된다. 상세와 새로고침 후 목록에 남는다. 기본 상태는 `todo`, 기본 우선순위는 `보통`이다.          |
| M-07 | 제목, 설명, 기존 담당자, 마감일, 우선순위 `높음`, 상태 `진행 중`, 태그 두 개를 입력해 저장한다. | 모든 필드가 상세에 정확히 표시되고 새로고침 후에도 유지된다.                                                 |
| M-08 | 새 TODO 입력 도중 취소한다.                                                                     | 입력 내용이 저장되지 않고 목록에 새 TODO가 생기지 않는다.                                                    |
| M-09 | 제목을 비우거나 공백만 입력한 뒤 저장을 시도한다.                                               | 저장되지 않고 제목 입력 오류가 표시된다. 입력한 다른 필드는 유지된다.                                        |
| M-10 | 생성 저장 버튼을 빠르게 여러 번 누른다.                                                         | 중복 TODO가 생성되지 않는다. 요청 중에는 중복 제출할 수 없다.                                                |
| M-11 | 기존 담당자를 선택해 생성한다.                                                                  | 상세의 담당자와 백엔드에 저장된 담당자 ID가 선택한 사람과 일치한다. 담당자를 선택하지 않아도 생성할 수 있다. |

### C. TODO 상세·수정·상태·삭제

| ID   | 절차                                                                                               | 기대 결과                                                                                                          |
| ---- | -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| M-12 | M-07 TODO의 제목, 설명, 담당자, 마감일, 우선순위, 상태, 태그를 모두 다른 값으로 수정하고 저장한다. | 모든 변경값이 상세와 목록에 반영되고 새로고침 후에도 유지된다.                                                     |
| M-13 | 상세에서 빠른 상태 변경으로 `할 일 → 진행 중 → 완료`를 차례로 적용한다.                            | 매 단계의 상태가 즉시 표시되고 새로고침 후에도 마지막 상태가 유지된다.                                             |
| M-14 | 편집 중 제목 등을 바꾸고 취소한다.                                                                 | 변경값이 저장되지 않고 이전 값이 다시 표시된다.                                                                    |
| M-15 | 담당자, 마감일, 설명을 비우고 태그를 모두 제거해 저장한다.                                         | 각 선택 필드가 비워지고 태그 목록은 빈 목록이 된다. 새로고침 후에도 복원되지 않는다.                               |
| M-16 | 태그를 두 개 입력해 저장한 뒤 하나만 남기고 다시 저장한다.                                         | 제거한 태그가 해당 TODO에서 사라지고 남긴 태그만 표시된다. 중복 태그를 입력해도 동일 태그가 두 번 표시되지 않는다. |
| M-17 | 편집 화면에서 제목을 공백으로 바꾸고 저장을 시도한다.                                              | 기존 TODO는 바뀌지 않고 입력 오류가 표시된다. 수정 중인 다른 입력은 유지된다.                                      |
| M-18 | 상세에서 삭제를 누른 뒤 확인 단계에서 취소한다.                                                    | TODO가 삭제되지 않고 상세에 그대로 남는다.                                                                         |
| M-19 | 자신이 만든 테스트 TODO의 삭제를 확인한다.                                                         | 목록으로 이동하고 삭제한 TODO가 목록에서 사라진다. 해당 상세 주소를 다시 열면 없는 TODO 안내가 나온다.             |
| M-20 | 존재하지 않는 ID의 `/tasks/999999999`로 직접 접속한다.                                             | 없는 TODO 안내와 목록으로 돌아가는 경로가 표시된다.                                                                |

### D. 설정 화면과 두 테마

| ID   | 절차                                                                      | 기대 결과                                                                                     |
| ---- | ------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| M-21 | 선택 기록이 없는 브라우저에서 앱을 열고 탐색 메뉴의 설정을 누른다.        | 앱은 목록으로 시작하며 별도 `/settings` 화면이 열린다. 기본 테마는 Kinetic Clarity이다.       |

### E. 장애·응답 오류·복구

| ID   | 절차                                                                                                                           | 기대 결과                                                                                        |
| ---- | ------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| M-25 | 백엔드를 잠시 중지한 뒤 `/tasks`를 새로고침한다. 백엔드를 다시 실행하고 재시도한다.                                            | 연결 실패 안내가 표시된다. 백엔드 복구 후 재시도하면 목록이 다시 열린다.                         |
| M-26 | TODO 편집 화면에서 값을 바꾸고 백엔드를 중지한 다음 저장을 시도한다. 백엔드를 다시 실행해 재시도한다.                          | 실패가 표시되고 입력값은 유지된다. 백엔드 복구 후 다시 저장하면 한 번만 반영된다.                |
| M-27 | 필수 제목 공백 등 유효하지 않은 입력으로 저장을 시도한다. 프론트엔드 검증을 통과했으나 API가 `422`를 반환하는 경우도 확인한다. | 어느 단계에서 거절되든 원인을 이해할 수 있는 입력 오류가 표시되며 완료된 것으로 표시되지 않는다. |
| M-28 | 삭제 요청이 실패하도록 백엔드를 중지한 상태에서 삭제를 확인하고, 복구 후 다시 시도한다.                                        | 실패 시 삭제된 것으로 표시하지 않고 상세에서 재시도할 수 있다. 복구 후 삭제된다.                 |

## 4. 실행 순서와 정리

1. M-01~M-05로 진입, 빈 상태, 목록을 확인한다.
2. M-06~M-11로 테스트 TODO를 만들고 ID를 기록한다.
3. M-12~M-20으로 해당 TODO의 수정·상태 변경·삭제를 검증한다.
4. M-21~M-24로 테마 전환과 저장을 확인한다.
5. M-25~M-30은 백엔드 중지와 화면 크기 변경이 필요하므로 별도로 실행한다.
6. 남은 테스트 TODO만 삭제한다. M-19로 삭제한 ID가 다시 조회되지 않는지 확인한다.

## 5. 통과 기준

- M-01~M-30의 기대 결과를 모두 확인한다.
- 생성·수정·상태 변경·삭제 결과는 새로고침 후에도 실제 백엔드 데이터와 일치한다.
- 오류가 발생해도 사용자의 미저장 입력을 잃거나 성공한 것처럼 표시하지 않는다.
- 두 테마와 모바일·데스크톱에서 동일한 핵심 작업을 완료한다.

이 문서의 브라우저 시나리오는 사용자가 직접 실행한다. Playwright E2E 테스트는 작성하거나 실행하지 않는다.
